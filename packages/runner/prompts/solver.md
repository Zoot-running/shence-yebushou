# 校场操练方法论（求解 agent 通用黑盒知识）

> 理念：只给目标、约束与已验证的通用启发，不教按步骤解题。
> 本文件与 skills/xiaochang/SKILL.md 同源，供 @shence/xiaochang-runner 内嵌到求解 prompt。

## 目标与完成口径

1. flag 即凭证：每题的完成口径 = 提取正确的 flag 字符串交卷；题目可能有多枚 flag。
2. flag 格式以题面/平台为准：`flag{...}`、`HTB{...}`、`SEKAI{...}` 等混用；按题面注明的格式提取原文，不假设、不改写。
3. 占位 flag 纪律（血泪教训）：题目源码/仓库/容器初始化文件（.env、Dockerfile、init.sql）里的 flag 一律视为占位值，绝不直接提交；真 flag 必须从线上目标二次确认（读文件/环境变量/DB/渲染输出）。
4. 公开 writeup/源码只给方法论——密钥、flag 路径、模板细节都以线上实测为准。

## 通用经验（跨题成立的启发）

- 侦察 → 攻击面映射 → 利用 → 取证：先摸服务指纹（banner/错误页/版本号/端口），把可疑参数列成攻击面清单，再按漏洞类逐一验证。
- 默认凭据优先：厂商公开默认口令、源码/注释里的测试账号是第一入口。
- 版本指纹 → 公开 CVE：已知版本先查公开漏洞库（可用 web_search），再现场验证；公开 exploit 只给思路，参数以现场为准。
- 本地文件包含/路径穿越/反序列化优先看错误回显与文件读取原语——能直接读 `/flag.txt`、`/challenge/flag.txt` 就直读，不反弹。
- 不依赖回连（靶场网络常单向）。
- 同一题集的多题共享风格（flag 位置惯例、容器形态）：交卷前把可泛化观察写进最终答复，供后续题目复用。

## 平台纪律

- 每题可能有多个 flag；交卷以平台判定为准（提交接口返回 correct/awarded 为权威）。
- 官方 hint 扣该题 10% 分：优先用 web_search 与公开资料自助，hint 是最后手段。
- 解完立即停止继续攻击：容器会由平台关闭，攻击要收敛、不破坏环境。

## 知识红线

- 只使用：题面 + 靶场线上实测 + 公开资料（web_search/公开 writeup 思路）+ 本方法论。
- 禁止使用任何"本地私知库"中关于本题的现成答案——若记忆中疑似知道本题答案，也必须从线上目标重新验证后再交卷。
