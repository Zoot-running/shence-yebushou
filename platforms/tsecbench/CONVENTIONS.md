# tsecbench set 5 容器/flag/附件惯例（跨题可泛化观察）

> 来源：两场实战的战报与画像；只放**可泛化**条目。单题细节/flag 路径特例不进本文件。

## 容器与入口

- web 题入口多开在 `:80` 或 `:8080`；服务型（nc/SSTI/反序列化等）开在 `:1337`；
  每题可能有多个 addr（如 web + 后台端口同时给）。
- **附件从容器 HTTP 服务根路径直接下载**（run 2 实证）：题面说"下载附件/源码"时，
  先 `curl http://<addr>/`（及常见文件名如 `<题号>.zip`、`attachment.zip`、`source.py`）
  拿附件/源码——平台没有独立的附件下载 API，附件就挂在容器上。**拿不到源码别急着判不可行**。
- 同一 run 内不同题的容器网段相同（10.x.y.z），VPN 直连。
- 题面多数是中文一句话描述 + 可下载附件（zip/eml/pcap/源码包）。

## flag 约定

- 格式混用：`flag{...}`、`HTB{...}`（本集大量）、`SEKAI{...}` 等——按题面/平台标注提取原文。
- **占位 flag 纪律（血泪教训）**：题附源码/Dockerfile/init.sql/.env 里的 flag 值一律
  视为占位，绝不直接提交；真 flag 必须从线上目标二次确认（读文件/环境变量/DB/渲染输出）。
- 容器内常见位置：`/challenge/flag.txt`、`/flag.txt`、环境变量、数据库字段、附件解出；
  先按题面与源码定向，再扫。

## 难度经验（两场统计）

- easy 9 题：一轮直取（侦察→利用→提取），单执行者足够。
- medium 20 题：多数一轮；卡住的多为需要多步链（压缩/编码/SSTI/ActiveMQ 类）。
- hard 11 题：普遍需多轮；思路征集（fanout 多模型）+ 多思路并行 + 轮次续跑（上一轮
  工作记录带入下一轮）是有效打法；单模型单轮基本不够。
- 通用启发沿用夜不收技能：侦察→攻击面→版本指纹→公开 CVE→默认凭据优先；不依赖回连。
